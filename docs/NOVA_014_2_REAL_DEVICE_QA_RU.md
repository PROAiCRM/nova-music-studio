## Публикация

1. Создать `https://github.com/PROAiCRM/nova-music-studio` как отдельный Public репозиторий (инициализировать README).
2. Загрузить файлы корня проекта, включая `index.html` и `qa/index.html`; не добавлять токены или аудиофайлы.
3. В GitHub Settings → Pages выбрать Source: Deploy from a branch, `main`, `/(root)`.
4. Проверить фактическое HTTPS открытие `https://proaicrm.github.io/nova-music-studio/`. Пока ссылка только ожидаемая.

## Испытание реальной синхронизации

Проводится только после публикации тестового экрана `qa/index.html` по HTTPS. Для регистрации использовать **отдельный тестовый email и уникальный пароль**, не пароль от основного аккаунта. Пароль тестовое приложение не сохраняет и не отправляет никому, кроме Supabase Auth.

1. На Mac открыть QA-экран, зарегистрировать тестовый аккаунт, подтвердить письмо, войти.
2. Нажать «Создать и отправить WAV». Приложение создаёт короткий синтетический сигнал; выдаёт ссылку.
3. На iPhone открыть ссылку, войти в тот же аккаунт и нажать «Проверить на устройстве». Сверяются таблица, аудиобайты и SHA-256.
4. При необходимости войти под отдельным тестовым аккаунтом B: тот же тест должен быть недоступен (отрицательный тест).
5. На Mac исходным аккаунтом A нажать «Удалить тестовые данные» и «Скачать отчёт JSON».
6. Результат включается в Evidence Register только после реальных PASS. При ошибке НЕ переносить личную библиотеку.

## Безопасность

QA-инструмент не содержит секретных ключей, сервисных токенов или личных файлов. Публичный publishable ключ Supabase — допустим для клиента; безопасность опирается на RLS и проверку JWT.

Никогда не вводить пароль от основного email в непроверенный тестовый сайт. Использовать отдельный тестовый пароль. Не публиковать пользовательские JWT, session storage, cookie, исходные личные записи и ссылки для приватной музыки.

При проблеме с удалением НЕ пытаться удалять объект прямым SQL из `storage.objects`; удалить через Storage API или административный интерфейс Supabase.

## Следующий архитектурный допуск

Только после PASS реального синтетического Mac↔iPhone теста — подключить личную медиатеку NOVA к постоянному адресу через ручной opt-in и полную предварительную резервную копию. Автоматическую миграцию не делать.
